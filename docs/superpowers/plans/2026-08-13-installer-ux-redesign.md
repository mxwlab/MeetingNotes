# MeetingNotes 安装体验整改计划

**目标：** 把当前“终端黑盒 + 8 行步骤 + 系统文件夹弹窗”整改成一个普通用户在 5 秒内能理解、等待时有安全感、完成后知道下一步的原生 macOS 安装流程。

**本计划只定义整改，不在本轮实施。** 当前安装能力、幂等升级、数据保留和日志机制继续作为底层，不推倒重写。

## 一、现状判断

2026-08-13 同机冷安装约 5 分钟，功能全部成功，但体验不合格：

1. 开始前没有说明将下载约 3–4 GB、通常需要多久、期间是否可以关闭。
2. `3/8`、`5/8`、`7/8` 只是阶段编号，不是用户能感知的总进度。
3. 依赖安装、2.2 GB 模型下载和 App 构建的详细进度只进日志，主窗口长时间静止。
4. 用户不知道当前是下载、校验、解压还是安装，也不知道卡住没有。
5. 失败态依赖阅读终端文字，没有明确的重试动作和错误归属。
6. 完成弹窗使用系统文件夹图标，却没有说明文件夹代表什么；唯一按钮“好”没有下一步价值。
7. 安装目录暴露 `/private/tmp/...` 或 `~/MeetingNotes` 技术路径，抢占了产品信息层级。

## 二、产品原则

- 安装是产品的第一个界面，不是脚本日志的可视化。
- 用户始终能回答三件事：**正在做什么、还要多久、我现在要不要操作。**
- 总进度基于真实工作权重，不用“第几步”伪装百分比。
- 主界面只显示任务、解释和动作；技术输出保留在“查看详细信息”折叠区。
- 长任务每 2 秒内必须有视觉反馈；网络下载尽量显示已下载体积和百分比。
- 完成页以“开始第一次使用”为目标，不以“安装脚本退出”为目标。
- 升级、重试和首次安装共用同一套界面，但文案与预计时间按实际缺失项变化。

## 三、推荐界面形态

制作一个随 zip 分发的轻量原生 `MeetingNotes 安装器.app`，用户右键打开一次。现有 shell 安装链继续负责实际工作，安装器只负责：

- 安装前预检与说明；
- 接收 shell 输出的结构化进度事件；
- 展示总进度、当前任务、状态说明与预计剩余时间；
- 提供 Key 输入、失败重试、查看日志与完成后的下一步。

不推荐继续把 Terminal 作为主界面，也不推荐用多个 AppleScript 弹窗串联模拟安装器。那两种方式都难以提供稳定的动态进度、错误恢复和一致视觉层级。

### 页面 1：准备安装

主标题：`安装 MeetingNotes`

正文只回答必要问题：

- `大约需要 5–10 分钟，取决于网络速度`
- `将下载约 3 GB，用于本机语音识别`
- `录音不会上传；只有转录文字会发送给你选择的 AI 服务`
- `安装过程中可以继续使用电脑，请不要关闭此窗口`

辅助信息：系统兼容、可用磁盘、网络状态。条件不满足时在此页阻断，不进入半安装状态。

主按钮：`继续`。次按钮：`取消`。不展示安装目录，放入“安装选项”折叠区。

### 页面 2：连接 AI 服务

- 默认 DeepSeek，说明“用于把本机转录文字整理成纪要”。
- Key 使用密码输入框，旁边提供“获取 API Key”。
- 点击 `验证并继续` 后显示验证中、成功或明确错误。
- 高级用户可展开“使用其他兼容服务”，默认不干扰朋友。

### 页面 3：安装中

稳定单窗口，不弹出 Terminal：

```text
正在安装 MeetingNotes                         62%
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━░░░░░░░░

正在下载本机语音模型
已下载 1.4 GB / 2.2 GB · 预计还需约 2 分钟

✓ 检查这台 Mac
✓ 保存 AI 服务设置
✓ 准备运行环境
✓ 安装音频工具
● 下载语音模型
○ 启动后台服务
○ 安装菜单栏小猫
○ 启用 AirDrop 自动处理

安装过程中可以继续使用电脑，请不要关闭此窗口。
                                   查看详细信息
```

设计要求：安静、原生、单一蓝色强调；不使用八张卡片、渐变背景或庆祝动画。步骤列表布局稳定，完成项只改变图标和文字颜色，不跳动。

### 页面 4：安装完成

使用 MeetingNotes 小猫或产品图标，不再使用系统文件夹图标。

标题：`MeetingNotes 已准备好`

正文：`把一段录音拖入“MeetingNotes 录音”，小猫会显示转录进度，完成后纪要会自动打开。`

动作层级：

1. 主按钮：`打开录音文件夹`
2. 次按钮：`查看使用方法`
3. 文字按钮：`完成`

同时明确展示：`菜单栏小猫已启动，并会在登录后自动出现。` AirDrop 成功则显示已启用；失败则显示非阻塞提醒和“稍后设置”，不能假装全部成功。

## 四、真实进度模型

安装脚本改为输出 JSON Lines 事件，UI 不解析自然语言日志：

```json
{"event":"plan","total_bytes":3221225472,"eta_seconds":420}
{"event":"step_start","id":"model","title":"下载语音模型","weight":45}
{"event":"download","id":"model","bytes":1503238553,"total":2362232012}
{"event":"step_done","id":"model"}
{"event":"error","id":"model","code":"network","message":"网络连接中断"}
```

初始建议权重按本次实测校准：

| 阶段 | 权重 | 用户解释 |
|---|---:|---|
| 兼容性与磁盘检查 | 3% | 确认这台 Mac 可以运行 |
| AI 服务设置 | 4% | 验证并安全保存 Key |
| Python 与依赖 | 25% | 准备本机处理环境 |
| ffmpeg | 5% | 安装音频读取工具 |
| Qwen 模型 | 48% | 下载本机语音识别模型 |
| 后台监听 | 4% | 自动发现新录音 |
| 菜单栏 App | 9% | 构建并启动状态小猫 |
| AirDrop | 2% | 启用自动接收 |

权重不是写死的装饰百分比：已缓存步骤应在安装前重新计算并从计划中降权；下载步骤使用真实字节进度，安装/构建步骤使用可验证子阶段。

剩余时间采用滚动速度估算，并使用柔和表达：`约 2 分钟`，不显示虚假的秒级精度。速度波动大时显示 `时间取决于网络速度`。

## 五、逐阶段整改任务

### Task 1：进度协议与可测安装状态机

涉及：`scripts/bootstrap_mac.sh`、各下载/置备脚本、新增 `scripts/progress.sh` 和协议测试。

- 为 8 个阶段定义稳定 ID、名称、权重、开始/进度/完成/警告/失败事件。
- Python、ffmpeg 和 Hugging Face 下载输出真实字节进度。
- pip 与 py2app 拆成“下载依赖 / 安装依赖 / 构建 App / 启动 App”子阶段。
- 保留纯文本兼容模式，便于日志和故障排查。
- 确保 JSON 事件绝不包含 API Key、用户路径中的敏感信息或 pip 技术噪音。

### Task 2：安装器原生壳

- 新增安装器工程与可复现构建脚本，发布包包含预构建 arm64 App，朋友无需 Xcode。
- 四页流程：准备 → AI 服务 → 安装中 → 完成。
- 启动 bootstrap 子进程，读取 stdout JSONL；stderr 写技术日志。
- 关闭窗口时若正在安装，明确询问“继续后台安装 / 停止安装”，不能直接消失。
- 支持 VoiceOver、键盘焦点、深色模式和 100%/125% 显示缩放。

### Task 3：预检与时间承诺

- 开始前检查 macOS、arm64、磁盘空间、网络与已有安装。
- 根据已存在的 Python、ffmpeg、模型和 UI 环境生成此次真实任务清单。
- 首次冷装展示约 5–10 分钟和约 3 GB；升级若无需下载则显示约 1–2 分钟。
- 磁盘不足时告诉用户“需要多少 / 当前多少 / 如何释放”，不让下载到一半才失败。

### Task 4：错误与恢复

- 网络、Key、磁盘、权限、模型校验、App 构建分别给可执行的中文错误。
- 主动作优先 `重试这一步`，而不是让用户退出后猜测是否重双击。
- 提供 `查看详细信息` 与 `打开日志文件`，但不要求普通用户理解日志。
- 已完成步骤继续保留；重试不能覆盖 Key、录音、纪要或已有模型。

### Task 5：完成态与首次使用

- 使用产品图标替换文件夹图标。
- 完成页显示后台、菜单栏、AirDrop 三项实际结果，部分失败不得统一显示“全部完成”。
- 主按钮打开桌面“MeetingNotes 录音”；同时通过菜单栏小猫做一次轻量高亮或通知，建立两者关系。
- 可选提供 10 秒示例音频的“试运行”，明确它会调用少量 DeepSeek 额度；默认不自动消费。

### Task 6：兼容入口与文档

- `开始使用.command` 变成兼容入口：优先打开安装器 App；安装器无法启动才回退终端模式。
- README 与图文教程更新为真实四页流程，不再用旧终端截图。
- 安装包首次打开、Key 页面、安装进度、完成页各补一张真实截图。

## 六、验收标准

### 可理解性

- 5 名未参与开发的人中，至少 4 人无需解释即可说出：需要多久、下载多大、音频是否上传、安装时是否要操作。
- 安装过程中任意时刻，测试者能在 5 秒内指出当前任务与预计剩余时间。
- 完成后至少 4/5 人无需提示即可找到“放录音”的入口。

### 反馈与可靠性

- 任何耗时超过 2 秒的任务都有动态状态；超过 10 秒同时显示解释或进度。
- 下载百分比与实际字节误差不超过 2%；总进度单调递增，不倒退、不长时间停在 99%。
- 拔网、磁盘不足、错误 Key、模型校验失败都能在当前页恢复。
- 第二次安装能识别已有内容，预计时间与步骤明显缩短。
- 退出、重试、升级均不丢失配置、录音、纪要和已完成下载。

### 完成态

- 不再出现无语义的系统文件夹完成弹窗。
- 完成页明确给出产品已启动、菜单栏位置、录音入口与 AirDrop 状态。
- 安装成功后无 Terminal 窗口残留。

## 七、实施顺序与工作量

1. **P0（0.5–1 天）**：先改善当前终端版——开始前给时间/体积承诺，每个阶段显示说明、完成勾选和耗时，结束弹窗改为明确按钮。可快速止血，但不作为最终体验。
2. **P1（1–1.5 天）**：结构化进度协议、下载字节进度、动态权重、错误分类及测试。
3. **P1（1.5–2.5 天）**：原生四页安装器、完成态、日志折叠与回退入口。
4. **P1（0.5–1 天）**：冷装、断网、重试、升级、深浅色与辅助功能验收；补真实截图。

合计约 **3.5–6 个开发日**。若只做 P0，黑盒感会缓解，但仍然是终端安装，不应把它当最终朋友版。

## 八、本轮不做

- 不借安装器整改顺带做自动更新、Windows、云端转录或账户体系。
- 不在没有证据时展示精确到秒的剩余时间。
- 不为了视觉效果伪造下载进度。
- 不自动上传日志、录音或纪要。
- 不用庆祝动画、渐变大卡片或营销式 onboarding 掩盖安装状态。
